# Gap Sense — Crossing Practice — iOS App

A native iOS build of the O&M street-crossing timing trainer, wrapped with
[Capacitor](https://capacitorjs.com/). The timing engine, the AudioContext-clock
replay synchronization, and the feedback-as-duration behavior are carried over
unchanged from the original `../index.html`; the presentation layer is new, and
haptics now reach the real iPhone Taptic Engine.

---

## What's in here

```
ios-app/
├── www/                      The app itself (this is what you edit)
│   ├── index.html            Entire app: UI + engine, one file, no build step
│   ├── manifest.webmanifest  PWA metadata (name, icons, standalone display)
│   ├── sw.js                 Service worker — offline caching for the web build
│   └── icons/                Generated app icons
├── ios/                      Native Xcode project (generated by Capacitor)
│   └── App/App.xcworkspace   <- open THIS in Xcode, not the .xcodeproj
├── capacitor.config.json     App id, name, splash/status-bar config
├── serve-lan.mjs             Test server that your phone can reach over Wi-Fi
├── make-icons.py             Regenerates icons if you change brand colors
└── make-splash.py            Regenerates the launch image
```

The original `../index.html` was left untouched as a reference.

## Path A — Test on your iPhone in about 2 minutes (no Xcode)

Use this first. It gets the real app onto your phone's home screen with its own
icon, running full screen, so you can walk outside and try it immediately.

**1. Start the server on your Mac**

```sh
cd ios-app
npm run lan
```

It prints something like:

```
On this Mac:   http://localhost:8000/
On your phone: http://192.168.1.87:8000/
```

**2. On your iPhone**

- Connect to the **same Wi-Fi network** as the Mac.
- Open **Safari** (it must be Safari, not Chrome) and type the
  `http://192.168.x.x:8000/` address.
- Tap the **Share** button (square with an arrow) → **Add to Home Screen** → **Add**.

You now have a "Gap Sense" icon on your home screen that opens full screen with
no Safari chrome.

**What works on this path:** everything except native haptics — all sounds,
the synchronized visual replay, every accessibility setting, themes, text scaling
to 300%, share links, VoiceOver.

**What doesn't:** vibration. iOS Safari has never implemented the web Vibration
API, so the "Vibrate on cue" switch does nothing here. That is exactly what
Path B fixes. Offline caching also won't kick in over plain LAN HTTP (service
workers need a secure origin), so keep the Mac's server running while testing.

## Path B — The real native app (Xcode)

This gives you a genuine `.app` on your phone, with **working Taptic Engine
haptics** and audio that ignores the ringer switch.

### B0. One-time Xcode setup — already done

Three things had to happen on this Mac before any iOS build could run. **All
three are complete**, and the project has been compiled and launched
successfully. Recorded here in case you need to repeat them on another machine.

1. **CocoaPods** was missing: `brew install cocoapods`
2. **Xcode first-launch components** had never been installed, so every
   `xcodebuild` failed with `xcodebuild failed to load a required plug-in`:
   `xcodebuild -runFirstLaunch` (no `sudo` needed)
3. **The iOS platform.** Xcode 15+ ships without device-support platforms; they
   are separate multi-gigabyte downloads. `-showsdks` listing "iOS 26.5" is
   misleading — the SDK is there, the *platform* is not, and builds fail with
   `iOS 26.5 is not installed`. Fixed with `xcodebuild -downloadPlatform iOS`
   (8.5 GB).

Confirm the machine is ready:

```sh
xcodebuild -workspace ios/App/App.xcworkspace -scheme App -showdestinations
```

**`Any iOS Device`** and the iPhone simulators should appear under *Available
destinations*. If they show under "Ineligible destinations" instead, redo step 3.

### B0b. Run it on the simulator first (no phone, no Apple ID)

The fastest way to see the native build. Already verified working:

```sh
xcrun simctl boot "iPhone 17"
open -a Simulator

xcodebuild -workspace ios/App/App.xcworkspace -scheme App \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -configuration Debug -derivedDataPath /tmp/DD build

xcrun simctl install "iPhone 17" /tmp/DD/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl launch "iPhone 17" com.gapsense.crossingpractice
```

Or just pick a simulator from Xcode's device dropdown and press ⌘R.

The simulator is good for layout, themes, dialogs, and the visual replay. It is
**not** useful for judging audio at roadside volume, and it has no Taptic
Engine — haptics need a real device.

### B1. Open the project

```sh
cd ios-app
npx cap open ios
```

Or open `ios/App/App.xcworkspace` manually.

> Open the **`.xcworkspace`**, never the `.xcodeproj` — the CocoaPods
> dependencies are only wired into the workspace.

### B2. Set up signing (free Apple ID is fine)

1. In Xcode's left sidebar, click the blue **App** project at the top.
2. Select the **App** target → **Signing & Capabilities** tab.
3. Tick **Automatically manage signing**.
4. **Team**: choose your Apple ID. If none is listed:
   Xcode → Settings → Accounts → **+** → Apple ID → sign in. Then come back and
   pick it.
5. **Bundle Identifier**: it is `com.gapsense.crossingpractice`. If Xcode says
   the identifier is unavailable, change it to something unique, e.g.
   `com.yourname.crossings`.

A free Apple ID works. See the expiry caveat in B6.

### B3. Prepare the iPhone

1. Plug the iPhone into the Mac with a cable. Tap **Trust This Computer** on the
   phone if asked.
2. On the phone: **Settings → Privacy & Security → Developer Mode → On**, then
   restart the phone. (This entry only appears after Xcode has tried to install
   something, so if you don't see it yet, do step B4 once first and come back.)

### B4. Build and run

1. In the device dropdown at the top of the Xcode window (next to the ▶ button),
   pick your iPhone by name.
2. Press **⌘R** (or the ▶ button).
3. First build takes a few minutes; later builds are much faster.

### B5. Trust the developer certificate

The first launch will fail with "Untrusted Developer". On the phone:

**Settings → General → VPN & Device Management → [your Apple ID] → Trust**

Then tap the app icon on the home screen. It will open.

### B6. The 7-day caveat (free accounts)

With a **free** Apple ID, the app stops opening after **7 days** and you must
re-run ⌘R from Xcode to refresh it. You are also limited to 3 sideloaded apps.

With a **paid** Apple Developer Program membership ($99/year), profiles last a
year and you get **TestFlight**, which lets you install on any iPhone over the
air and invite up to 10,000 testers — the right choice once O&M instructors
start testing it.

## What to test on the device

The things that can only be judged on real hardware:

- [ ] **Sound at roadside volume.** Take it outside near traffic. Are the
      "acceptable" chime and the "outside" pulse each clearly audible, and
      clearly *different from each other*, through the phone speaker?
- [ ] **Ringer switch.** Flip the physical silent switch on. Sounds should still
      play (this is what the `AVAudioSession` change in `AppDelegate.swift` buys
      you). If they stop, tell me.
- [ ] **Haptics.** Accessibility → tick "Vibrate on cue" → **Test haptic pulse**.
      You should feel three distinct pulses: a medium tap, a light triple, and a
      heavy buzz. The note under the button tells you which haptics backend is
      live — in the native build it should read "Native haptics active".
- [ ] **VoiceOver.** Turn it on (Settings → Accessibility → VoiceOver) and run a
      full practice. Note especially whether the double-tap-to-activate delay
      throws off your marking accuracy — that is an open design question
      (tracked as `uc-j9n`), not a bug I can fix from here.
- [ ] **Text size 300%.** Accessibility → Text size → Maximum. Every control
      should stay reachable and nothing should be clipped or overlap.
- [ ] **All four themes**, especially Light while your phone is in dark mode.
- [ ] **The visual replay**, in Audio + Visual mode: full-screen black, grey
      flash for your marks, green circle for acceptable, orange triangle for
      outside.

## Making changes

The app is still one editable file: **`www/index.html`**.

**For Path A (PWA):** just save the file and reload in Safari. If a stale
version sticks, bump `CACHE_VERSION` in `www/sw.js`.

**For Path B (native):** after editing, copy your changes into the native
project and rebuild:

```sh
npx cap sync ios      # copies www/ into ios/App/App/public
```

then ⌘R in Xcode again.

> `npx cap sync ios` currently prints a long `xcodebuild` plugin error at the
> end. The web assets still copy correctly (that part succeeds first). Once you
> have run `sudo xcodebuild -runFirstLaunch` from B0, the error goes away. If you
> only changed files under `www/`, `npx cap copy ios` is enough and skips the
> failing step entirely.

**Changing the brand color:** edit `BRAND_TOP` / `BRAND_BOTTOM` in
`make-icons.py` and `make-splash.py`, re-run both scripts, then update the
matching CSS custom properties (`--brand-1`, `--brand-2`) near the top of
`www/index.html`.

**Tuning sounds and timing:** search `www/index.html` for `const TEST_TUNING`
and `const SOUND_PRESET_LIBRARY`. Both have a plain-English guide comment
directly above them. Keep the sum of each preset's partial gains at or below
about 0.80 — beyond that you are just feeding the master limiter.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `xcodebuild failed to load a required plug-in` | `xcodebuild -runFirstLaunch` (already done here) |
| `iOS 26.5 is not installed` / no destinations / ▶ greyed out | `xcodebuild -downloadPlatform iOS` (step B0) |
| `CocoaPods is not installed` | `brew install cocoapods` (already done on this Mac) |
| App launches to a blank screen | Usually just the splash still showing — wait a second. If it persists, check that `ios/App/App/public/index.html` exists; if not, run `npx cap copy ios` |
| Phone can't reach the LAN address | Same Wi-Fi network? Some routers block client-to-client traffic ("AP isolation") — try a phone hotspot instead |
| "Untrusted Developer" on launch | Step B5 |
| App won't open after a week | Free-account 7-day expiry — re-run ⌘R (step B6) |
| No sound in the native app | Check the ringer switch, then confirm `configureAudioSession()` is still in `AppDelegate.swift` |
| Haptics do nothing | Confirm "Vibrate on cue" is ticked; check the support note text under the Test button; haptics never work in iOS Safari (Path A) |
| Signing error about bundle ID | Change it to something unique, e.g. `com.yourname.crossings` (step B2) |

## Known limitations

- **No App Store submission yet.** That needs a paid developer account, a
  privacy policy, and store assets. The app collects nothing and makes no
  network calls, so the privacy questionnaire is trivial — but it is still a
  separate piece of work.
- **No attempt history.** Results are still discarded at reset, so the adaptive
  margin-of-error feature and any data export remain blocked on a persisted
  attempt log.
- **Android is not set up.** The same project would take it — `npm i
  @capacitor/android && npx cap add android` — but that was outside this task.
- **Two timing systems still coexist.** Audio runs on the drift-free
  AudioContext clock; UI stage changes and haptics run on `setTimeout`. Close
  enough in practice, but on a loaded device the visuals and haptics can drift
  slightly from the sound. Driving everything from the replay timeline is the
  real fix and is a larger refactor.
